# OpenFEC API Integration

## Overview

This dashboard integrates real campaign finance data from the [Federal Election Commission's OpenFEC API](https://api.open.fec.gov/).

## Features Implemented

### ✅ Real-time FEC Data Fetching
- Candidate search by name and office (House/Senate)
- Financial summaries (receipts, disbursements, cash on hand)
- Donor breakdowns:
  - PAC vs Individual contributions
  - Small donors (<$200) vs Large donors (≥$200)
  - Percentage calculations
- Top contributors list
- Comprehensive error handling and caching

### ✅ Data Pipeline Integration
- Pipeline fetches FEC data for all 535 members of Congress
- Data is cached at build time in `src/data/finance.json`
- Dashboard can fetch live data on-demand via `getMemberFinance()`
- Falls back to static data if API is unavailable

### ✅ Testing
- **Unit tests** (`src/lib/fec.test.ts`): Mock API responses, test error handling
- **Integration tests** (`src/lib/fec-integration.test.ts`): Real API calls with actual data validation
- All tests passing ✓

## API Key Setup

### Getting an API Key

1. Sign up at https://api.data.gov/signup/
2. API key will be emailed instantly
3. Free tier: 1,000 requests/hour (more than enough for our pipeline)

### Configuration

Add to `.env`:

```bash
FEC_API_KEY=your_api_key_here
```

Or use 1Password:

```bash
source ~/.secrets && op read "op://Aria Labs/OpenFEC/credential"
```

## Usage

### In the Data Pipeline

The pipeline automatically fetches FEC data for all members:

```bash
npm run pipeline
```

Configuration in `pipeline/sources/fec.ts`:
- Batch size: 2 requests at a time (to avoid rate limits)
- Delay: 6 seconds between batches
- Retries: Automatic retry on transient errors

### In the Dashboard

The dashboard loads finance data with:

```typescript
import { getMemberFinance } from '@/lib/data';

// Fetches from FEC API, falls back to static data
const finance = await getMemberFinance(bioguideId);
```

Finance data includes:
```typescript
{
  candidate_id: string;
  cycle: number;
  total_raised: number;
  total_spent: number;
  cash_on_hand: number;
  individual_contributions: number;
  pac_contributions: number;
  party_contributions: number;
  candidate_self_funding: number;
  small_donors: number;
  large_donors: number;
  pac_percentage: number;
  small_donor_percentage: number;
  large_donor_percentage: number;
  top_contributors: Array<{
    name: string;
    total: number;
    count: number;
    type: 'individual' | 'pac' | 'party' | 'committee';
  }>;
  top_industries: Array<{
    industry: string;
    total: number;
  }>;
}
```

## API Endpoints Used

### 1. Candidate Search
**Endpoint:** `/candidates/search/`

**Purpose:** Find FEC candidate ID by name

**Parameters:**
- `q`: Candidate name (format: "LASTNAME, FIRSTNAME")
- `office`: H (House) or S (Senate)
- `cycle`: Election cycle (default: 2024)

**Rate limit:** 1000/hour

### 2. Financial Totals
**Endpoint:** `/candidate/{candidate_id}/totals/`

**Purpose:** Get comprehensive financial summary

**Returns:**
- Total receipts/disbursements
- Individual/PAC/party contributions
- Cash on hand
- Small vs large donor breakdown

**Rate limit:** 1000/hour

### 3. Top Contributors
**Endpoint:** `/candidate/{candidate_id}/schedules/schedule_a/by_contributor/`

**Purpose:** Get top contributors (itemized)

**Note:** Some candidates may have empty results if they don't accept large donations (e.g., Bernie Sanders)

**Rate limit:** 1000/hour

## Caching Strategy

To minimize API calls and improve performance:

1. **In-memory cache** (5-minute TTL)
   - Stores API responses during runtime
   - Prevents duplicate requests
   - Cleared on server restart

2. **Static build cache** (`src/data/finance.json`)
   - Pre-fetched data for all members
   - Generated by pipeline
   - Used as fallback if API fails

3. **Incremental updates**
   - Pipeline can be run daily via GitHub Actions
   - Only updated data is fetched
   - Old data remains available

## Error Handling

The integration gracefully handles:
- Missing API key (falls back to static data)
- Rate limiting (exponential backoff)
- Network errors (retry with backoff)
- Candidate not found (returns null)
- Invalid responses (logs error, returns null)

## Data Quality

### Validation
- All monetary values are positive numbers
- Percentages sum to ≤100% (with tolerance for rounding)
- Individual contributions = small donors + large donors
- Types are strictly enforced (TypeScript)

### Known Limitations
1. **Top contributors may be empty**
   - Some candidates don't have itemized contributions
   - Grassroots-funded candidates (e.g., Bernie Sanders) may show 0

2. **Industry data not available**
   - OpenFEC doesn't provide industry breakdowns
   - Would need OpenSecrets API for this

3. **Historical data limited**
   - Current cycle only (2024)
   - Past cycles available but not currently fetched

## Performance

### Pipeline
- ~535 members × 2 API calls = ~1,070 requests
- At 2 requests/batch with 6s delay: ~50 minutes total
- Can be optimized by increasing batch size with production API key

### Dashboard
- First load: API fetch (~500ms)
- Subsequent loads: In-memory cache (<1ms)
- Fallback: Static file (~5ms)

## Troubleshooting

### API key invalid error
```
Error: API_KEY_INVALID
```
**Solution:** Check `.env` file or get a new key from api.data.gov

### Rate limit exceeded
```
Error: RATE_LIMIT (429)
```
**Solution:** Wait 1 hour or use a production API key with higher limits

### Candidate not found
```
No FEC candidate found for [Name]
```
**Reason:** 
- Name mismatch (FEC uses "LASTNAME, FIRSTNAME" format)
- Candidate hasn't filed with FEC yet
- Office mismatch (H vs S)

**Solution:** Falls back to static data automatically
